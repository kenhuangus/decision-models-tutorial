The Problem Statement

Why Generative LLMs Fail at Decision-Making

Standard LLMs are trained for autoregressive next-token prediction. When used for routing, policy gating, or verification, this architecture produces systemic vulnerabilities.

Generative LLM Failure Modes

VulnerabilityMechanismImpact on Agents
Format Drift Model adds conversational filler or markdown markers around JSON. Breaks downstream execution parsers and crashes agent loops.
Uncalibrated Logits Softmax probability is smeared across token variations ("yes", "Yes", " True"). Cannot establish trustworthy confidence thresholds for high-risk actions.
Latency Penalty Autoregressive decoding loop executes sequentially token by token. 200ms–2000ms delay just to determine a 1-bit routing decision.
Temperature Noise Stochastic sampling creates non-deterministic routing on identical states. Inconsistent behavior in mission-critical CI/CD and security filters.

What Decision Models Deliver Instead

  • Single Forward Pass: Evaluates entire context and outputs logits in one step (no decoding loop).
  • Strict Output Constancy: Returns normalized vectors over predefined discrete classes or booleans.
  • True Calibration: A probability score of 0.85 means the model is empirically accurate 85% of the time.
  • Zero Parsing Failure: Direct tensor readout completely eliminates string matching and regex parsing.
System Architecture

Lifting the Causal Mask: How Decision Models Work

Decision models transform standard transformer backbones by eliminating the autoregressive decoding barrier.

Standard Generative Architecture (Causal Mask)

[Token 1] ──► attends only to [Token 1] [Token 2] ──► attends to [Token 1, Token 2] [Token N] ──► attends to [Token 1 ... Token N] │ ▼ [Full Vocab LM Head (150,000+ tokens)] │ ▼ Generate Token N+1 (Autoregressive Loop)

Tokens cannot attend forward. Full vocabulary projection is computationally heavy and suffers from distribution dispersion.

Decision Model Architecture (Lifted Mask + Readout)

[Full Input State] ──► Bi-directional Attention (No Causal Mask) Every token attends to all other tokens │ ▼ [Last Hidden Layer Vector (h_L)] │ ▼ [Dedicated Readout Head (BF16 Tensor)] │ ▼ [Calibrated Softmax Probabilities (P_1 ... P_K)]

Full bi-directional context representation. The output is directly projected onto target choice indices in a single forward pass.

System Integration Patterns

How to Integrate Decision Models with AI Agents & LLMs

Production architectures decouple creative reasoning from deterministic control using the Sandwich Architecture Pattern.

1. Ingress Guardrail

Decision Model: Evaluates raw user input for prompt injection, jailbreaks, and policy compliance.

if decider.decide(prompt)["noul"] > 0.85: raise SecurityException("Attack blocked")

2. Generative Core

Generative LLM (Claude/GPT/Qwen): Synthesizes code, technical prose, complex plans, and conversational dialogue.

response = llm.generate( system=PROMPT, user=clean_prompt )

3. Egress Verifier

Decision Model: Inspects generated response for hallucination (NLI) and credential leakage before dispatch.

if decider.decide(response)["contradicted"] > 0.8: regenerate(response)

  • Sub-Millisecond Multi-Agent Consensus: In multi-agent swarms, agents can vote on plan branches using decision heads in parallel without token consumption.

Model Adaptation

Fine-Tuning Decision Models: Architecture & Parameter Isolation

Adapting general-purpose decision models to proprietary enterprise ontologies without catastrophic forgetting or high GPU memory overhead.

1. Why Fine-Tune Decisions?

Generative SFT teaches conversational style and syntax. Decision SFT establishes calibrated probability thresholds across domain-specific taxonomy boundaries (e.g. SOC incident containment vs false-positive alarms).

  • Domain-calibrated decision margins
  • Enforce strict operational policies
  • Eliminate out-of-distribution hallucinations

2. Readout Head Isolation

The 4-billion parameter bi-directional backbone is frozen via torch.no_grad(). Only the specialized projection matrix W_readout ∈ ℝ255 × 5120 is trained.

decider.backbone.eval() for p in decider.backbone.parameters(): p.requires_grad = False decider.readout.requires_grad_(True)

Saves full language priors while keeping memory usage under 6 GB RSS.

3. Hardware & Operational Efficiency

Because backpropagation stops at the readout head, gradient computation requires zero recurrent state caching across the backbone sequence.

  • Checkpoint Weight: Exactly 2,611,280 bytes (2.6 MB)
  • Hardware: Apple Silicon Unified RAM (Metal MPS)
  • Iteration Speed: 12 epochs in ~90 seconds on Mac Mini
  • Zero GPU Cluster: Runs locally on commodity hardware
Supervised Formulation

Dataset Engineering & The Compound Decision Loss

Decision models require structured state-question-target triplets optimized with a calibrated loss that resists overconfidence.

Decision Training Sample Schema

Each example defines an observed environmental state, schema criteria, and an exact target distribution vector (hard one-hot or soft committee distribution):

{ "state": "Active Cobalt Strike beaconing from host 10.0.4.12 to 198.51.100.23. C2 confirmed.", "questions": { "triage": { "type": "choice", "criteria": { "containment": "Isolate host, revoke tokens immediately.", "investigation": "Pull memory pcaps, triage alert.", "false_positive": "Authorized testing or benign tool." } } }, "target": [1.0, 0.0, 0.0] # Soft: [0.85, 0.15, 0.0] }

Compound Loss: Cross-Entropy + Brier Calibration

Standard Cross-Entropy drives outputs toward 1.0, creating extreme overconfidence. We combine CE with a quadratic Brier score penalty:

# 1. Cross-Entropy Loss on Target Distribution log_prob = F.log_softmax(logits / decider.temperature, dim=-1) ce_loss = -(target * log_prob).sum() # 2. Brier Calibration Penalty (ensures probability curvature) brier_loss = (log_prob.exp() - target).square().sum() # 3. Compound Decision Objective (λ = 0.15) total_loss = ce_loss + 0.15 * brier_loss
Mathematical Property: Minimizing Brier score strictly optimizes probability calibration, ensuring confidence scores match actual empirical hit rates.
Implementation Code

End-to-End Fine-Tuning Pipeline (PyTorch on MPS)

Production script that fine-tunes the decision head on Apple Silicon Metal Performance Shaders.

Step 1 · Collation & Frozen Backbone Pass

import torch, torch.nn.functional as F from pplx_decider.model import Decider from pplx_decider.protocol import left_pad decider = Decider(snap_path, device="mps") decider.readout.requires_grad_(True) optimizer = torch.optim.AdamW(decider.readout.parameters(), lr=1e-3, weight_decay=1e-4) for item in training_data: optimizer.zero_grad() chunk = decider.encoder.encode({"state": item["state"], "questions": question}) inputs = {k: v.to("mps") for k, v in left_pad([chunk], decider.encoder.pad_id).items()} with torch.no_grad(): hidden = decider.backbone(**inputs, use_cache=False).last_hidden_state

Step 2 · Loss Backpropagation & Export

# Align question marker token with readout tensor offsets = [inputs["input_ids"].shape[1] - chunk.length] row, col = torch.tensor([0], device="mps"), torch.tensor([chunk.markers[0] + offsets[0]], device="mps") logits = decider.readout(hidden[row, col])[0, :3] log_p = F.log_softmax(logits / decider.temperature, dim=-1) target = torch.tensor(item["target"], device="mps") loss = -(target * log_p).sum() + 0.15 * (log_p.exp() - target).square().sum() loss.backward(); optimizer.step() # Export tuned readout weights (2.6 MB) from safetensors.torch import save_file save_file({"weight": decider.readout.weight.cpu()}, "finetuned_readout.safetensors")

Field Diagnostics

Diagnostic Engineering Log: Issues Identified & Resolved

Four concrete runtime failure modes discovered and solved during live model installation and fine-tuning on Apple Silicon.

Issue 1 · Encoder Signature Mismatch

Symptom: Passing a batch list decider.encoder.encode([req], max_length=...) triggered a TypeError: unexpected keyword argument 'max_length'.

Resolution: The protocol encoder is synchronous per-item. Encode single requests individually, then collate via pplx_decider.protocol.left_pad(chunks, pad_id).

Issue 2 · Missing CUDA/Triton Kernels on Darwin ARM64

Symptom: Fallback warnings for causal_conv1d_fn and chunk_gated_delta_rule due to absence of CUDA Triton kernels on Apple Silicon.

Resolution: PyTorch reference implementation runs with exact numerical parity on MPS, sustaining ~850ms per forward pass with zero stability issues.

Issue 3 · Calibration Drift Under Unregularized Cross-Entropy

Symptom: Cross-entropy alone drives output logits into saturation, producing 0.9999+ confidence on out-of-distribution edge cases after merely 3 epochs.

Resolution: Added quadratic Brier penalty λ = 0.15 to the loss function. Brier penalizes extreme probability distances, maintaining smooth calibrated margins.

Issue 4 · VRAM Exhaustion During Recurrent Backprop

Symptom: Unfreezing full 4B parameters requires holding backward attention caches across recurrent delta layers, threatening unified memory exhaustion.

Resolution: Froze entire backbone with torch.no_grad(). Backpropagated solely into the 2.6 MB readout head, reducing peak RSS to 5.48 GB.
Curriculum Synthesis

The 4 Golden Rules of Decision Models

Core architectural principles to remember when building production AI Agent systems.

Rule 1 · Never Generate When You Can Classify

If the output of a step is a routing destination, a true/false gate, or a category choice, never prompt a generative model to produce text. Use a decision model to obtain direct, calibrated probabilities.

Rule 2 · Lift the Mask for State Context

Decision models allow bi-directional cross-attention across the entire input state, eliminating position biases and token-order decay inherent in standard causal attention masks.

Rule 3 · Calibrated Confidence Enables Automation

Calibrated probabilities let you set mathematically rigorous thresholds (e.g. execute autonomously if >0.90, route to human review if between 0.60–0.90, reject if <0.60).

Rule 4 · Pair Decision Gates with Generative Synthesis

Place decision models at ingress (prompt injection filters), at execution branching (tool selection), and at egress (hallucination & PII filters) around generative models.
